Field guide

Promotion scraper field guide

Everything the scraper can do today, and the command for each. Seven retailers, four tools, thirteen test suites.

Start here

Run everything from the code folder. These four cover most of what you'll need:

# 1. What retailers are available
python run.py --list-retailers

# 2. A quick look at one brand
python run.py --retailer lookfantastic --brands Clinique --max-products 15

# 3. Everything a site is promoting, no brands needed
python run.py --retailer boots --campaigns-only

# 4. Check nothing is broken before you change anything
python run_tests.py -q
Two habits worth keeping. Add --cache-dir .cache while experimenting so re-runs cost the retailer nothing, and drop it for real runs so prices are live. Add --archive to any run you might want to compare against later — without it, change tracking has nothing to diff.
Run retailers one at a time. Five of the seven drive a real browser, and running them together starves DNS and browser resources on one machine. A Lookfantastic pass that takes 54 minutes on its own took 30 hours alongside two others, with 51 requests failing on ERR_NAME_NOT_RESOLVED — a local DNS failure, not anything the retailers did. Budget roughly an hour per retailer, in series.

The four tools

ToolWhat it answers
run.pyWhat is this retailer charging and promoting for our brands?
compare.pyWhere does one retailer undercut another on the same product?
changes.pyWhat moved between two runs — prices, offers started and ended?
spotcheck.pyDoes a record actually match the live page?
run_tests.pyDid I break anything? (13 suites, 356 checks, no network)

Recipes

Real questions, and the command that answers them.

Which of our brands is Look Fantastic discounting right now? 
python run.py --retailer lookfantastic \
    --brands Clinique MAC "Tom Ford" "Jo Malone" "Estee Lauder" \
    --archive
Open the per-brand CSVs in output/. --archive keeps a timestamped copy so you can diff against it later.
What campaigns is a competitor running site-wide? 
python run.py --retailer lookfantastic --campaigns-only
No brands needed. Returns every promotion on the offers hub with its landing page and an honest scope. Works for Look Fantastic and Boots; John Lewis has no central offers hub, so it refuses rather than returning an empty file.
Who is cheapest on the same product? 
python run.py --retailer lookfantastic --brands Clinique --out-dir output/compare
python run.py --retailer boots        --brands Clinique --out-dir output/compare
python run.py --retailer johnlewis    --brands Clinique --out-dir output/compare

python compare.py output/compare/*.json
Matches products across retailers by title and size, then reports the price gap. Raise --threshold for stricter matching.
What changed since last week? 
python run.py --retailer boots --brands Clinique --archive   # do this weekly
python changes.py --latest --retailer boots
Reports price moves, discounts started and ended, and products that appeared or vanished. Needs at least two archived runs.
Is this data actually right? 
python spotcheck.py --retailer boots \
    --from-output output/boots_clinique.json --sample 10
Re-fetches a sample and prints what it extracted, with the URL, so you can compare against the live page yourself.
Prepare for Black Friday 
python run.py --retailer boots --brands Clinique --archive        # baseline now
python run.py --retailer boots --brands Clinique --archive \
    --offer-keywords keywords/black-friday.txt                    # on the day
python changes.py --latest --retailer boots
A keyword file replaces the built-in offer rules, so black-friday.txt deliberately re-includes everyday retail wording. Edit the file directly — no code changes.
Only skincare, not the whole brand 
python run.py --retailer boots --brands Clinique --categories skincare
Or keep full coverage and label categories afterwards with --resolve-categories. John Lewis needs neither — it states the category on the product page.
Highest confidence data only 
python run.py --retailer lookfantastic --brands Clinique --strict-brand
Accepts only products whose brand comes from the retailer's structured data. Fewer records, no inference.

Every run.py flag

FlagEffect
--retailerAdapter name or any URL — boots, boots.com, https://www.boots.com/clinique
--brandsOne or more; quote names with spaces. Matched leniently, so "Jo Malone" finds Jo Malone London
--categoriesRestrict to categories. Refuses on a retailer that can't honour it, rather than ignoring you
--resolve-categoriesKeep full coverage but label each product's category afterwards
--campaigns-onlyEvery campaign on the site, no products, no brands required
--offer-keywordsA keyword file that replaces the built-in offer rules
--max-productsCap per brand. For demos — omit for a full pass
--strict-brandStructured-data brand evidence only
--archiveKeep a timestamped copy under output/history/ for change tracking
--cache-dirCache responses so re-runs cost no requests
--crawl-dirCheckpoint, so an interrupted run resumes
--out-dirWhere results go (default: output/ next to the script)
--list-retailersPrint the available adapters and exit

What you get back

Each run writes one JSON document, one products CSV per brand, plus campaigns and rejections.

CollectionColumns
Productsretailer, brand, brand_matched_to, category, product_title, product_id, sku, current_price, price_is_from, original_price, discount_amount, discount_percent, currency, availability, variant_count, promotional_copy, applied_campaigns, product_url, brand_verified_by, scraped_at
Campaignscampaign_id, retailer, scope, scope_value, promotion_type, promotion_text, promo_code, landing_url, source_url
Rejectedreason, detail, source_url, product_title, product_id

Two columns worth understanding

price_is_from — the page quoted a range ("£33.60 – £156.00"), so the price is the cheapest size, not a specific item. Never compare it against another retailer's single-size price.

brand_verified_by — how we proved the brand: json_ld_brand and breadcrumb_link are the retailer's own structured claim; anything weaker is visible so you can audit it.

Campaign scopes

Every campaign says how far it reaches, read from where its link points rather than guessed.

scopeMeaning
sitewideRuns across the whole site. Never tagged to a brand
brandTied to one brand — "20% off Medik8"
categoryTied to a department — "20% Off Luxury Beauty"
productThe offer on one product's own page
unresolvedReal offer, reach not provable from the page. Honest, not a failure

Why a record gets rejected

Rejections go to _rejected.csv with a machine-readable reason — never silently dropped, because a rejection usually means a page changed.

reasonCatches
missing_titleNo product name could be read
missing_priceNo current price could be read
invalid_discountWas-price below the now-price — impossible
discount_mismatchAdvertised % disagrees with the two prices
unverified_brandBrand not provable from the retailer's own data
weak_brand_evidenceBrand inferred rather than stated (--strict-brand only)
brand_mismatchVerified brand isn't one you asked for
variant_conflictSKU belongs to a different product than the URL

Before you change anything

.venv\Scripts\python.exe run_tests.py -q

Thirteen suites and 356 checks, no network, a few seconds. They run against captured real pages, so they catch extraction drift as well as logic errors. Green before you start and green after you finish means you didn't break what was working.
